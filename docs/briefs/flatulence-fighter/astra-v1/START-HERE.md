# Flatulence Fighter: complete art and design handoff

Open `previews/contact_a_identity.jpg` for the identity, `previews/style_play.png` and `previews/style_intertitle.png` for the proposed screen direction. There is one contact sheet for every asset section.

1. Read `ASSESSMENT.md` for the screenshot review, prioritized improvements and selling risks.
2. Read `STYLE-GUIDE.md` for palette, typography, scenes, cast and motion.
3. Integrate one complete Funeral loop using `dev/INTEGRATION.md`, then map the remaining scenes.
4. Use `manifest.json` for exact sizes, state names, alpha windows and slice values.
5. Run the phone acceptance checks in the integration guide before producing real store captures.

## Contents

| Section | Delivered |
|---|---|
| A Identity | Outlined wordmarks and PNGs, three app icons, feature graphic, arcade tile, launch frame, social card |
| B Stage | Twelve 900x1600 scenes, two mood plates, paper and grain tiles, iris overlay, nine-slice card frame |
| C Player | Five editable SVG rigs; six individual SVG and transparent PNG expressions for each character |
| D Onlookers | Twelve matching backs/turned pairs, two or three people per room; bus, books and radio-lamp props |
| E Icons | Complete monochrome SVG control, mode, difficulty, cover-noise and feedback set |
| F Controls | Six HOLD plates, three VENT plates, abilities, charge dots, cooldown ring, meters, pips, leaks, banners and intertitle |
| G Wardrobe | Eighteen vector medal marks, five portraits, four palette plaques, frame, lock and equipped mark |
| H Sharing | Square and portrait result frames, square Daily frame, exact face windows and text bands |
| I Store | Six 1080x1920 blank screenshot overlays with headline and real-capture windows |

`NOTES.md` records choices and synthesized-sound direction. `QA.md` records asset checks and remaining runtime checks. `dev/palette_and_controls.css` is a reference specification, not a tested patch to the live game. `dev/asset_preview.html` opens locally and lets the team inspect scene, cast and expression combinations without a server or build step.

The source archive contained screenshots, not runnable game code. These are finished art assets and a concrete development handoff, not a claim that the live game is updated. Store frames must be filled with real captures after integration; the style previews are labeled proposals.
